# Eidolon Observer Deployment Guide

## Static Export

The observer frontend uses Next.js static export (`output: 'export'`). This means:

- ✅ Fully pre-rendered HTML/CSS/JS at build time
- ✅ No server needed — hosted as static files on GitHub Pages
- ✅ Fast global CDN delivery
- ❌ No SSR, API routes, or `getServerSideProps` — these won't work with static export
- ❌ No live backend integration — the UI fetches from static JSON

## Demo Mode

The observer currently runs in **demo mode**. It loads `simulation-snapshot.json` from `frontend/public/`, which is a bounded 50-tick simulation snapshot generated by `generate_snapshot.py`.

This is **not** the permanent architecture. A live backend would need to be hosted separately with CORS enabled for the observer to fetch real-time data.

## Deployment Steps

### 1. Push to main
The GitHub Actions workflow automatically builds and deploys on push to `main`.

### 2. Verify the Action
Go to **Actions** tab in the GitHub repo → confirm `Deploy Observer to GitHub Pages` succeeds.

### 3. Open the Pages URL
The deployed URL is typically: `https://<user>.github.io/<repo-name>/`

### 4. Check for 404s
Open browser DevTools → Console → look for asset 404s. If you see 404s for assets, it's likely a `basePath`/`assetPrefix` mismatch. The `next.config.js` reads `NEXT_PUBLIC_BASE_PATH` from the environment.

### Manual Local Build
```bash
cd frontend
NEXT_PUBLIC_BASE_PATH=/eidolon npm run build
```

## GitHub Pages Settings

In the GitHub repo:
1. Go to **Settings** → **Pages**
2. Set **Build and deployment** → **Source** to **GitHub Actions**
3. The workflow handles everything — no need to configure the source branch

## What Can't Work Yet
- Live agent simulation in the browser (requires backend)
- Real-time event streaming (requires WebSocket/SSE)
- Interactive controls (would need API routes)

The static export approach works for visualization and replay but not for live interaction.
